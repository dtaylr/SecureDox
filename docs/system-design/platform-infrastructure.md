# Platform Infrastructure

SecureDox uses a deliberately small platform layer that proves DevOps/SRE
competency without burying the product in infrastructure.

## Local Runtime

- Docker Compose runs Postgres, Redis, API, worker, web, Nginx, Prometheus, and
  Grafana.
- Nginx handles reverse proxy routing, request ID forwarding, correlation ID
  propagation, security headers, rate limits, upload size limits, and timeouts.
- Health checks exist at the service and compose level.

## Terraform

Terraform lives under `infra/terraform` with:

- A reusable `modules/securedox_stack` module.
- Separate `envs/local` and `envs/staging` roots.
- Variables, validations, outputs, and idempotent deployment-plan state through
  Terraform's built-in resource type.

The module is credential-free by design, so reviewers can run `terraform init`
and `terraform validate` locally.

## Ansible

Ansible lives under `infra/ansible` and demonstrates:

- SSH-based host management.
- Linux hardening.
- Docker installation and daemon configuration.
- Monitoring agent setup.
- Idempotent playbooks and syntax-checkable roles.

## Kubernetes

Minikube manifests live under `infra/k8s/minikube` and include:

- Deployments, Services, and Ingress.
- ConfigMap and Secret example.
- Readiness and liveness probes.
- Rolling update strategy.
- HPA for API and worker services.

## Platform Gates

Platform evidence is generated by:

- `make terraform-validate`
- `make ansible-check`
- `make kube-validate`
- `make iac-scan`
- `make checkov`
- `make test-platform`
